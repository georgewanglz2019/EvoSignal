# EvoSignal

**大语言模型引导的模块化交通信号控制程序进化设计**

EvoSignal 在**离线设计阶段**利用大语言模型改进可检查的交通信号控制程序。选定的程序直接根据交通观测选择相位，**在线运行时无需调用大语言模型**。

> **论文展示版。** 本仓库目前只提供研究介绍和图表。预印本公开后会补充 arXiv 链接；完整代码与复现材料计划在论文接收后发布。

## 研究动机：让自适应控制规则仍然可检查

交通需求和路网会变化。人工调节显式控制规则费时；神经网络和大语言模型控制器虽能适应交通反馈，但其决策通常不易作为代码直接检查，在线运行也需要模型推理。EvoSignal 用交通运行反馈同时改进**交通特征计算**与**相位优先级规则**，部署时直接执行得到的程序。

| 能力 | 传统信号控制 | 强化学习控制 | 大模型控制 | EvoSignal |
| :--- | :---: | :---: | :---: | :---: |
| 根据交通性能反馈改进策略 | ✗ | ✓ | ✓ | ✓ |
| 利用预训练大模型知识 | ✗ | ✗ | ✓ | ✓ |
| 在线语言推理与决策解释 | ✗ | ✗ | ✓ | ✗ |
| 自动修订显式交通特征代码 | ✗ | ✗ | ✗ | ✓ |
| 自动修订显式相位优先级规则 | ✗ | ✗ | ✗ | ✓ |
| 决策规则可作为代码直接检查 | ✓ | ✗ | ✗ | ✓ |
| 决策规则可作为代码直接编辑 | ✓ | ✗ | ✗ | ✓ |
| 在线无需神经模型推理 | ✓ | ✗ | ✗ | ✓ |
| 预期在线计算开销 | 低 | 取决于模型 | 通常较高 | 低 |

*这是对各类代表性方法的定性比较，不是实测排名，也不代表每一种具体实现。传统方法指预设规则控制器；强化学习方法指神经网络策略。大模型类别包括利用交通反馈训练的模型。实际在线开销受实现、模型规模、硬件、批处理和生成长度等因素影响。*

## 方法概览

![EvoSignal 离线程序进化框架](assets/figures/evosignal-framework.svg)

*论文图 2。多策略初始化（Multi-init）提供起点；三模块程序包含交通特征（M1）、局部相位优先级（M2）及可选的路网感知修正（M3）。仿真性能分析（SPA）诊断交通行为，帕累托策略档案（PSA）保留不同性能权衡的策略，为后续修订提供参考。选定程序在线运行时不调用大模型。*

## 论文中的主要结果

- **等待时间：**在两个真实路网的五个场景中，默认选定程序的等待时间比各场景 **20 个传统、强化学习和大模型基线中的最低等待时间**降低 **16.8–49.2%**。
- **跨场景迁移：**侧重行程时间与排队长度的程序在 J1 搜索场景的三项指标上均优于全部 20 个基线；未经修改迁移到其余四个场景后，每项指标仍排在前三。

![论文表 2：济南三个场景中 20 个基线与进化程序的交通控制结果](assets/figures/table-2-jinan.png)
